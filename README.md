# flashrec

Відновлення файлів із флешок, що відмовляють. Безкоштовно, з відкритим кодом,
з графічним інтерфейсом і командним рядком.

flashrec створено для типового випадку: Windows пише «Відформатувати диск?»,
том показується як RAW, `chkdsk` лише погіршує справу. Програма **ніколи нічого
не пише на диск, який відновлюється**: знімає посекторний образ і далі працює з
ним, відновлюючи імена файлів і структуру тек із залишків MFT.

## Що вміє

| Етап | Що робить |
|---|---|
| **Образ** | Посекторна копія диска блоками по 1 МіБ. Блок, що не прочитався, перечитується посекторно; нечитані сектори заповнюються нулями, **але рахуються** і записуються у файл `.map` — дірку ніхто не прийме за дані. Перерване зняття можна продовжити. |
| **Сканування** | Знаходить том NTFS (за MBR, за підписом або на зсуві 0), читає основний або **резервний** завантажувальний сектор, далі йде за runlist-ом `$MFT`. Коли `$MFT` зламаний — **перебирає весь том у пошуках записів `FILE`**. |
| **Відновлення** | Відновлює дерево тек за батьківськими посиланнями, витягає вміст за runlist-ами (зокрема розріджені файли) і видалені файли, чиї записи ще не перезаписано. Файл, у якому частину кластерів не прочитано, отримує суфікс `.НЕПОВНИЙ`. |
| **Вирізання** | Останній засіб, коли метаданих не лишилося: знаходить файли за вмістом — JPEG, PNG, GIF, PDF, ZIP/DOCX/XLSX, RAR, 7z, документи Office, MP3, MP4/MOV, SQLite. Імен і тек не повертає. |

## Запобіжники

- **Серійний номер.** Номери дисків зсуваються, коли пристрої підключають і
  виймають. GUI запам'ятовує серійний номер обраного диска й відмовляється
  знімати образ, якщо під тим самим номером уже інший пристрій. У CLI для цього
  є `--expect-serial`.
- **Не на той самий диск.** Записати образ чи відновлені файли на диск, з якого
  відновлюєте, не вийде: програма питає Windows, на якому фізичному диску лежить
  тека, і відмовляє.
- **Жодних тихих втрат.** Нечитаний сектор, пошкоджений запис MFT, стиснений
  чи зашифрований файл, якого flashrec не розкодовує, — усе потрапляє у звіт.
  Файли, яких не вдалося відновити цілими, позначено в назві.
- **Кілька флешок.** Якщо знімних дисків кілька, GUI не обирає жодного сам —
  серед них майже напевно і той, куди пишеться результат.

## Як користуватися

Запускайте **від імені адміністратора**: без цього Windows не дасть читати
фізичний диск. Файли образів відкриваються й без прав адміністратора.

### Графічний інтерфейс

`flashrec-gui.exe` веде крок за кроком:

1. **Джерело** — оберіть флешку (звірте модель і серійний номер) або файл образу.
2. **Зняти образ** — вкажіть файл на *іншому* диску. Щойно образ готовий,
   програма сама перемикається на нього, і флешку можна вийняти.
3. **Сканувати** — якщо нічого не знайдено, увімкніть «Перебір підписів».
4. **Відновити** — оберіть теку. Таблицю можна відфільтрувати й відновити
   лише показане.
5. **Вирізати** — лише якщо сканування нічого не дало.

Результат лягає в `ТЕКА\наявні\…` і `ТЕКА\видалені\…`.

### Командний рядок

```
flashrec list
flashrec image   --disk 2 --expect-serial AA00BB11CC22 --out D:\відновлення\flash.img
flashrec scan    --image D:\відновлення\flash.img
flashrec recover --image D:\відновлення\flash.img --out E:\відновлення\файли
flashrec carve   --image D:\відновлення\flash.img --out E:\відновлення\вирізане
```

Відновити лише частину — за підрядком шляху, без огляду на регістр:

```
flashrec recover --image D:\відновлення\flash.img --out E:\відновлення\файли --path Документи,Фото
flashrec recover --image D:\відновлення\flash.img --out E:\відновлення\файли --exclude-path Office\Data
```

`flashrec --help` — повний перелік параметрів.

## Порада щодо швидкості

Пишіть образ на **внутрішній SSD**, а не на іншу флешку. Антивірус
перечитує файл образу, поки той росте, і на USB-флешці це може сповільнити
зняття в десятки разів: під час розробки образ на флешку йшов зі швидкістю
~400 КіБ/с, а той самий образ на NVMe — ~20 МБ/с.

## Чого flashrec не робить

- не розкодовує стиснені (NTFS compression) і зашифровані (EFS) файли — вони
  позначаються й пропускаються, а не записуються сміттям;
- не працює з FAT32/exFAT — лише NTFS (вирізання за сигнатурами працює на
  будь-якій файловій системі);
- не читає таблиці розділів GPT — лише MBR, а також пошук тому за підписом;
- не лікує сам носій. Для фізично мертвого контролера потрібна лабораторія.

## Збирання

Потрібен Rust 1.82 або новіший.

```
cargo build --release
```

Бінарники з'являться в `target\release\`: `flashrec.exe` (командний рядок) і
`flashrec-gui.exe` (графічний інтерфейс).

Рушій `flashrec-core` і командний рядок не мають жодних зовнішніх залежностей —
шлях порятунку даних збирається навіть без інтернету. Графічному інтерфейсу
потрібні `eframe`/`egui` і `rfd`.

```
cargo test
```

## Будова

Інтерактивна схема архітектури —
[`.archify/architecture-flashrec-20261026-192059/flashrec.html`](.archify/architecture-flashrec-20261026-192059/flashrec.html):
завантажте файл і відкрийте в браузері. Джерело схеми — `candidate.json` поруч;
кожен вузол посилається на рядки коду, з яких його намальовано.

```
crates/
  flashrec-core/   рушій без залежностей
    sys.rs           біндінги Win32: DeviceIoControl і IOCTL дисків
    device.rs        перелік дисків, сире читання, запобіжник «не той диск»
    reader.rs        побайтове читання поверх секторного
    imaging.rs       зняття образу зі збійними секторами
    partition.rs     пошук тому NTFS в образі
    ntfs/            завантажувальний запис, записи MFT, runlist, відновлення
    carve.rs         вирізання за сигнатурами
    source.rs        спільне відкриття джерела для CLI і GUI
  flashrec-cli/    командний рядок
  flashrec-gui/    графічний інтерфейс на egui
```
